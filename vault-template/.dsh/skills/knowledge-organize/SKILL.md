# 知识理

## 拆卡方案选择

触发 `知识理` 后询问以下两个选项：

1. **用户自定义（custom）**：用户为每篇待处理来源填写原子知识卡数量，以及每张卡片要包含的标题或核心内容。
2. **AI 推荐（recommend）**：由大模型阅读每篇来源，按可独立复用的稳定问题推荐卡片数量和每张卡片的核心内容。

执行规则：

- 排除文件名以 `_` 开头的说明文件并列出待处理来源；用户已明确选择 `custom`、`recommend` 或对应中文选项时不重复询问。
- `custom`：用户填写卡片数量、标题或核心内容；信息不完整时请其补齐，数量须与内容条目数一致。用户方案优先，但若需编造来源外知识，须在写入前说明冲突并请其调整。
- `recommend`：按独立问题、流程完整性、规则边界和复用价值推荐数量、标题与核心内容后直接执行；仅当来源为空、重复、已完整处理或无可复用知识时可推荐 `0`，并说明原因。
- 两种方案均不得为凑数量创建空卡、重复卡，或拆断不可分割的流程。

## 共同执行要求

1. 一张卡片回答一个稳定问题，并包含独立结论、适用场景、方法或解释、示例以及限制；必须依赖同一上下文或流程才能理解的内容继续合并保存。
2. 边界不清、证据不足或价值暂不确定的细节继续留在来源笔记，或在卡片中标为“限制 / 待补充”，不得写成已确认事实。
3. 原子卡片使用 `05_Skills/0501_Knowledge Management/050101_Templates/知识卡片模板.md`，设置 `type: knowledge-skill`。
4. 每张卡片必须填写完整 Skill 式检索属性：`description`、`aliases`、`triggers`、`use_when`、`do_not_use_when`、`match_questions`、`parent_index`、`source_notes` 和 `related`。
5. `description` 使用“当用户需要……时使用。包含……；不包含……”格式，明确调用边界，不能只重复标题。
6. 原子卡片通过 `source_notes` 链接来源笔记；来源笔记的“已提炼知识”反向列出全部卡片。
7. 来源含 SOP 或操作流程时，“实施方法”必须完整保留前置条件、输入、步骤、参数、验证、异常处理和注意事项；相关图片（含截图、图表）须紧跟对应内容嵌入，附件保存在 `07_Attachments/`；模板标题无对应来源内容时可删除，不得补写或省略已有内容。
8. 为每张卡片选择 `route_to`，填写 `route_reason` 和 0–1 的 `route_confidence`。
9. 目标知识包必须创建或更新 `_Index.md`，登记文档路由、本目录文档和相关知识包；新增知识包时还必须按层级同步：
   - **一级知识包**（直接位于 `02_Domains` 至 `05_Skills` 的编号主题目录，如 `05_Skills/0502_SAP操作`）：更新根目录 `知识路由索引.md` 和所在分类的顶层索引。
   - **二级知识包**（位于一级知识包下，如 `05_Skills/0502_SAP操作/050201_跑成本`）：更新一级知识包的 `_Index.md` 和所在分类的顶层索引；仅当一级入口或边界改变时更新根目录 `知识路由索引.md`。
10. 置信度不低于 0.85 时设为 `status: ready`，运行路由脚本执行移动；低于 0.85 时设为 `status: needs-review`，继续留在 Inbox。
11. 本轮方案中的全部原子卡片完成后，来源笔记路由到 `06_Archive` 的来源目录，保留完整追溯链，不删除原文和附件。

## 知识理：完成前自检清单

在报告 `知识理` 完成前，必须逐项自检：

1. **方案**：是否只提供“用户自定义 / AI 推荐”两个选择，并按所选方案确定每篇来源的卡片计划。
2. **数量**：实际创建的卡片数量、标题和核心内容是否与方案一致，且没有空卡、重复卡或把无关主题硬塞进同一卡片。
3. **内容完整性**：每张卡片是否独立回答一个稳定问题；关键结论、数字、代码、名称、示例和限制是否有来源依据，不确定内容是否标为风险或待补充。
4. **YAML**：每张 `knowledge-skill` 是否具备完整检索属性；`description` 是否明确适用与排除边界；`source_notes` 与来源笔记的“已提炼知识”是否形成真实双向链接。
5. **图文**：SOP 的实施方法是否完整；相关图片、截图、PDF 或图表是否紧跟对应说明，附件路径是否真实存在；没有来源内容的模板章节是否已删除。
6. **路由**：是否按第 9 条更新目标、父级、所在分类及根知识路由索引；`route_to`、`route_reason`、`route_confidence` 和状态是否一致；低于 0.85 或边界不清的卡片是否留在 Inbox；是否先预览再执行并核对结果，且未删除、覆盖、合并或移动用户未确认的资料和附件。

## 自动移动条件

自动移动必须同时满足：

```yaml
status: ready
route_to: 03_Areas/Research
route_confidence: 0.90
```

其中 `route_confidence` 必须不低于 `0.85`。脚本默认只预览，增加 `--apply` 后才执行移动。

## 文件夹编号

路由创建新文件夹时必须自动编号：

```text
05_Skills/0502_主题
05_Skills/0503_主题
06_Archive/0601_主题
05_Skills/0502_主题/050201_子主题
```

规则：

- 同级第一个新目录从 `01` 开始，之后取现有最大编号加一。
- 已存在的同名旧目录可以直接复用，不重复创建。
- 已存在但未编号的旧目录不会被脚本擅自重命名。
- 如果 `route_to` 使用无编号的新目录名称，脚本会生成编号并把最终路径回写到笔记属性。
- 手工创建目录或由 AI 直接创建目录时，也必须使用相同规则。

```powershell
# 预览
python ".agents/scripts/knowledge_router.py"

# 执行
python ".agents/scripts/knowledge_router.py" --apply

# 巡检
python ".agents/scripts/knowledge_router.py" --audit
```
