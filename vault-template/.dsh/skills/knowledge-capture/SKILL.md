# 知识收

## 知识收 / 知识理模式确认

当用户触发 `知识收` 或 `知识理` 时，AI 必须先询问使用 `精简模式` 还是 `保真模式`，再开展读取、解析、写入、拆卡、更新索引或路由等后续工作。

如果用户已在同一条指令中明确指定模式，例如 `知识收 精简`、`知识收 保真`、`知识理 精简` 或 `知识理 保真`，则按指定模式执行，不重复询问。

## 知识收：精简模式

精简模式用于快速入库和后续再处理，目标是“先收进来、能追溯、保留核心证据”，不追求完整复原全部背景。

操作要求：

1. 只读处理来源文件或当前对话；不得移动、覆盖或写回源文件。
2. 只读取足以理解核心内容的范围；图片、截图和短文档可直接查看，长文档可只保留核心页、核心段落或关键转录。
3. 附件需要保存时，复制到 `07_Attachments/` 的合适编号目录；不需要复制时，至少记录来源文件名、位置和原因。
4. 来源笔记仍使用 `05_Skills/0501_Knowledge Management/050101_Templates/Inbox 收集模板.md` 的基本结构，但可压缩章节。
5. 来源笔记至少包含：
   - 来源说明
   - 核心摘要
   - 关键原文 / 转录 / 表格片段
   - 附件链接或嵌入
   - 必要风险提示
   - 建议提炼的知识卡片
6. 不主动展开完整推理、详细保真偏差、长篇背景、完整知识清单或复杂版本比对。
7. 价值不确定的信息可汇总到“待补充 / 未确认”，但不得省略安全风险、关键证据或用户明确指出的重要信息。
8. 来源笔记设置 `type: source`、`status: inbox`、`retrieval_priority: low`。
9. 写入后确认来源笔记和已复制附件实际存在，再报告保存路径。

## 知识收：保真模式

保真模式用于 专业或业务规则、主数据、表格、图文资料、流程制度或需要长期追溯的内容，目标是“尽量避免静默丢失知识”。

操作要求：

1. 只读处理来源文件；需要解析、转换或规避文件锁时，优先创建临时副本，完成后删除临时副本。
2. 记录来源文件名、用户指定范围、文件大小、最后修改时间、可验证哈希和处理边界。
3. 完整保留原始问题、真实需求、背景与约束、完整知识清单、推理与决策过程、方法步骤、示例、代码或配置、适用条件、例外与风险、行动项、重要原文和未解决问题。
4. 无法确认是否应删除的信息，放入“补充细节”或“重要原文”，不得直接省略。
5. 图片、截图或图表应保存为附件，并在对应文字说明后用 Obsidian 可渲染语法引用，优先使用 `![[07_Attachments/...]]`。
6. 表格、PDF、图文混排资料应说明已保留内容和保真偏差；不能用摘要冒充原始资料。
7. 在“建议提炼的知识卡片”中列出后续可拆分主题，但 `知识收` 阶段不创建原子卡片、不直接归档。
8. 来源笔记设置 `type: source`、`status: inbox`、`retrieval_priority: low`。
9. 输出后核对源文件大小和修改时间未变化，确认来源笔记、附件或快照实际存在。

## 知识收：共同安全底线

1. 不把密码、令牌和登录凭据写入知识库。
2. 银行账号及其他敏感业务或个人信息默认不入库；只有用户对指定文件和范围作出明确授权时才可保留，并记录授权边界。
3. 文件名不得包含 `\ / : * ? " < > |`。
4. 只有当对话包含互不相关的多个主题时，才拆成多篇来源笔记，并通过 `related` 互相链接。

## 知识收：完成前自检清单

在报告 `知识收` 完成前，必须逐项自检：

1. 是否已按用户选择的精简模式或保真模式执行；如果用户未指定模式，是否已经先询问。
2. 来源文件是否只读处理，未移动、覆盖或写回源文件。
3. 来源笔记是否已创建，且 `type: source`、`status: inbox`、`retrieval_priority: low` 正确。
4. 来源说明、核心摘要、关键原文 / 转录、附件链接和待提炼主题是否已保留。
5. 如有附件，附件是否已复制到 `07_Attachments/` 的合适编号目录，并能从来源笔记链接或嵌入。
6. 图片、截图、PDF 或图表是否在对应文字说明后引用；如果无法显示或无法转换，应说明保真偏差。
7. 表格资料是否按默认保真模式处理；若使用精简模式，是否说明 Markdown 不能替代原表。
8. 是否检查并避免写入密码、令牌、登录凭据等禁止信息。
9. 如涉及客户代码、账号、主数据等敏感业务信息，是否记录用户授权范围和访问风险。
10. 是否确认来源笔记和附件实际存在；必要时核对源文件大小、修改时间和哈希未变化。

## 表格资料模式选择

处理 `.xlsx`、`.xlsm`、`.csv`、`.tsv` 等结构化表格资料时，默认使用 `保真模式`。

如果用户明确要求对表格资料使用 `精简模式`：

1. 不逐行逐列展开原始表格，不声称 Markdown 已完整保留原表。
2. 必须保留原始附件；若不复制附件，必须记录源文件路径、文件大小、最后修改时间和可验证哈希。
3. 只写核心摘要、字段说明、关键原文 / 表格片段、必要风险和待提炼主题。
4. 如果涉及 专业或业务规则、主数据、公式、敏感字段、审计追溯或长期复核，应提示用户建议改用 `保真模式`。
5. 精简模式下的统计、摘要和异常提示只能作为辅助说明，不能替代原始表格。

## Excel 与结构化表格保真处理规则

Excel、CSV 和 TSV 的原始表格或用户指定工作表是权威来源，Markdown 只承担索引、背景、字段解释和分析结论，不能替代原表。保真模式必须遵守：

1. 原始文件或用户指定工作表是权威来源，始终保持只读，不覆盖、不重算、不另存回源文件。
2. 用户限定工作表、区域或表对象时，只读取该范围；不得为了“完整”擅自读取其他工作表或区域。
3. 必须逐行、逐列保留用户指定范围，不得静默抽样、聚合、去重、删除空行空列或只保留分析结论。摘要、统计和异常检查只能作为附加层。
4. 优先用原格式表格附件保留完整信息；Markdown 来源笔记负责说明和链接，不得冒充能无损替代 Excel。
5. 原样保留至少包括：工作表名、区域、行列顺序、表头、空值、数据类型、公式与缓存值、错误值、合并单元格、隐藏行列、筛选、冻结窗格、批注、数据验证、命名区域及格式。无法保留的项目必须逐项写入“保真偏差”。
6. 对大型表格，应保存完整附件或拆分后的完整数据文件，不得以篇幅为由省略明细。拆分文件必须能按原始行号和列号重新组合。
7. 来源在 Vault 外时，默认不移动或改写。若原文件未复制进 Vault，必须记录文件名、指定工作表 / 区域、文件大小、最后修改时间和可验证哈希，并明确原文件仍是唯一完整副本。
8. 复制附件前先检查敏感信息。密码、令牌和登录凭据不得复制到知识库。银行账号及其他敏感业务或个人信息默认不复制；只有用户对指定文件、工作表和保存范围作出明确授权时才可保留，并必须记录授权范围和访问风险。脱敏副本不得标为“原样副本”。
9. 输出后核对源文件大小和修改时间未变化，并检查表格快照 / 附件实际存在、可打开且范围完整。
10. 表格摘要、指标、分类和异常检查均是原表之上的派生知识，不得反向覆盖原始数据。
