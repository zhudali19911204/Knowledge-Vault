# 知识路由规则

## 核心流程

```text
收集 → 提炼 → 分类 → 连接 → 检阅 → 输出
```

## 默认整理架构

无论选择精简模式还是保真模式，默认都使用“来源笔记 + Skill 化原子卡片 + 目录 `_Index.md`”三层结构；差异在于来源笔记和原子卡片的保留粒度。

```text
来源笔记
  保存来源、核心证据；保真模式完整保存背景、推理、细节、原文和待补充内容
        ↓ 知识理
knowledge-skill 原子卡片
  每张卡片独立回答一个稳定问题，并声明使用与排除边界
        ↓ 知识联
knowledge-package 目录索引
  像 SKILL.md 一样根据需求路由到主文档和相关文档
```

AI 回答问题时先读取根目录 `知识路由索引.md`，再进入对应目录 `_Index.md`，默认只加载一篇主文档和最多三篇相关文档。只有正式知识不足时才回看来源笔记。

## 知识收 / 知识理模式确认

当用户触发 `知识收` 或 `知识理` 时，AI 必须先询问使用 `精简模式` 还是 `保真模式`，再开展读取、解析、写入、拆卡、更新索引或路由等后续工作。

如果用户已在同一条指令中明确指定模式，例如 `知识收 精简`、`知识收 保真`、`知识理 精简` 或 `知识理 保真`，则按指定模式执行，不重复询问。

## 知识收：精简模式

精简模式用于快速入库和后续再处理，目标是“先收进来、能追溯、保留核心证据”，不追求完整复原全部背景。

操作要求：

1. 只读处理来源文件或当前对话；不得移动、覆盖或写回源文件。
2. 只读取足以理解核心内容的范围；图片、截图和短文档可直接查看，长文档可只保留核心页、核心段落或关键转录。
3. 附件需要保存时，复制到 `07_Attachments/` 的合适编号目录；不需要复制时，至少记录来源文件名、位置和原因。
4. 来源笔记仍使用 `05_Skills/0501_Knowledge Management/050101_Templates/Inbox 收集模板.md` 的基本结构，但可压缩章节。
5. 来源笔记至少包含：
   - 来源说明
   - 核心摘要
   - 关键原文 / 转录 / 表格片段
   - 附件链接或嵌入
   - 必要风险提示
   - 建议提炼的知识卡片
6. 不主动展开完整推理、详细保真偏差、长篇背景、完整知识清单或复杂版本比对。
7. 价值不确定的信息可汇总到“待补充 / 未确认”，但不得省略安全风险、关键证据或用户明确指出的重要信息。
8. 来源笔记设置 `type: source`、`status: inbox`、`retrieval_priority: low`。
9. 写入后确认来源笔记和已复制附件实际存在，再报告保存路径。

## 知识收：保真模式

保真模式用于 专业或业务规则、主数据、表格、图文资料、流程制度或需要长期追溯的内容，目标是“尽量避免静默丢失知识”。

操作要求：

1. 只读处理来源文件；需要解析、转换或规避文件锁时，优先创建临时副本，完成后删除临时副本。
2. 记录来源文件名、用户指定范围、文件大小、最后修改时间、可验证哈希和处理边界。
3. 完整保留原始问题、真实需求、背景与约束、完整知识清单、推理与决策过程、方法步骤、示例、代码或配置、适用条件、例外与风险、行动项、重要原文和未解决问题。
4. 无法确认是否应删除的信息，放入“补充细节”或“重要原文”，不得直接省略。
5. 图片、截图或图表应保存为附件，并在对应文字说明后用 Obsidian 可渲染语法引用，优先使用 `![[07_Attachments/...]]`。
6. 表格、PDF、图文混排资料应说明已保留内容和保真偏差；不能用摘要冒充原始资料。
7. 在“建议提炼的知识卡片”中列出后续可拆分主题，但 `知识收` 阶段不创建原子卡片、不直接归档。
8. 来源笔记设置 `type: source`、`status: inbox`、`retrieval_priority: low`。
9. 输出后核对源文件大小和修改时间未变化，确认来源笔记、附件或快照实际存在。

## 知识收：共同安全底线

1. 不把密码、令牌和登录凭据写入知识库。
2. 银行账号及其他敏感业务或个人信息默认不入库；只有用户对指定文件和范围作出明确授权时才可保留，并记录授权边界。
3. 文件名不得包含 `\ / : * ? " < > |`。
4. 只有当对话包含互不相关的多个主题时，才拆成多篇来源笔记，并通过 `related` 互相链接。

## 知识收：完成前自检清单

在报告 `知识收` 完成前，必须逐项自检：

1. 是否已按用户选择的精简模式或保真模式执行；如果用户未指定模式，是否已经先询问。
2. 来源文件是否只读处理，未移动、覆盖或写回源文件。
3. 来源笔记是否已创建，且 `type: source`、`status: inbox`、`retrieval_priority: low` 正确。
4. 来源说明、核心摘要、关键原文 / 转录、附件链接和待提炼主题是否已保留。
5. 如有附件，附件是否已复制到 `07_Attachments/` 的合适编号目录，并能从来源笔记链接或嵌入。
6. 图片、截图、PDF 或图表是否在对应文字说明后引用；如果无法显示或无法转换，应说明保真偏差。
7. 表格资料是否按默认保真模式处理；若使用精简模式，是否说明 Markdown 不能替代原表。
8. 是否检查并避免写入密码、令牌、登录凭据等禁止信息。
9. 如涉及客户代码、账号、主数据等敏感业务信息，是否记录用户授权范围和访问风险。
10. 是否确认来源笔记和附件实际存在；必要时核对源文件大小、修改时间和哈希未变化。

## 表格资料模式选择

处理 `.xlsx`、`.xlsm`、`.csv`、`.tsv` 等结构化表格资料时，默认使用 `保真模式`。

如果用户明确要求对表格资料使用 `精简模式`：

1. 不逐行逐列展开原始表格，不声称 Markdown 已完整保留原表。
2. 必须保留原始附件；若不复制附件，必须记录源文件路径、文件大小、最后修改时间和可验证哈希。
3. 只写核心摘要、字段说明、关键原文 / 表格片段、必要风险和待提炼主题。
4. 如果涉及 专业或业务规则、主数据、公式、敏感字段、审计追溯或长期复核，应提示用户建议改用 `保真模式`。
5. 精简模式下的统计、摘要和异常提示只能作为辅助说明，不能替代原始表格。

## Excel 与结构化表格保真处理规则

Excel、CSV 和 TSV 的原始表格或用户指定工作表是权威来源，Markdown 只承担索引、背景、字段解释和分析结论，不能替代原表。保真模式必须遵守：

1. 原始文件或用户指定工作表是权威来源，始终保持只读，不覆盖、不重算、不另存回源文件。
2. 用户限定工作表、区域或表对象时，只读取该范围；不得为了“完整”擅自读取其他工作表或区域。
3. 必须逐行、逐列保留用户指定范围，不得静默抽样、聚合、去重、删除空行空列或只保留分析结论。摘要、统计和异常检查只能作为附加层。
4. 优先用原格式表格附件保留完整信息；Markdown 来源笔记负责说明和链接，不得冒充能无损替代 Excel。
5. 原样保留至少包括：工作表名、区域、行列顺序、表头、空值、数据类型、公式与缓存值、错误值、合并单元格、隐藏行列、筛选、冻结窗格、批注、数据验证、命名区域及格式。无法保留的项目必须逐项写入“保真偏差”。
6. 对大型表格，应保存完整附件或拆分后的完整数据文件，不得以篇幅为由省略明细。拆分文件必须能按原始行号和列号重新组合。
7. 来源在 Vault 外时，默认不移动或改写。若原文件未复制进 Vault，必须记录文件名、指定工作表 / 区域、文件大小、最后修改时间和可验证哈希，并明确原文件仍是唯一完整副本。
8. 复制附件前先检查敏感信息。密码、令牌和登录凭据不得复制到知识库。银行账号及其他敏感业务或个人信息默认不复制；只有用户对指定文件、工作表和保存范围作出明确授权时才可保留，并必须记录授权范围和访问风险。脱敏副本不得标为“原样副本”。
9. 输出后核对源文件大小和修改时间未变化，并检查表格快照 / 附件实际存在、可打开且范围完整。
10. 表格摘要、指标、分类和异常检查均是原表之上的派生知识，不得反向覆盖原始数据。

## 知识理：精简模式

精简模式用于快速把 Inbox 中最有复用价值的内容变成可检索知识，目标是“少拆卡、先可用、保留追溯”。

操作要求：

1. 排除文件名以 `_` 开头的说明文件。
2. 只提炼最核心、最稳定的 1–2 张 `knowledge-skill` 原子卡片；没有足够价值时可以只做 1 张或暂不建卡。
3. 边界不清、证据不足、价值暂不确定的细节继续留在来源笔记，或在卡片中标为“限制 / 待补充”，不为凑数量制造碎片。
4. 每张卡片仍必须填写必要的 Skill 式检索属性：`description`、`aliases`、`triggers`、`use_when`、`do_not_use_when`、`match_questions`、`parent_index`、`source_notes` 和 `related`。
5. `description` 仍使用“当用户需要……时使用。包含……；不包含……”格式，明确使用边界。
6. 如果有与卡片直接相关的图片、截图或图表，应放在对应文字说明之后，优先使用 `![[07_Attachments/...]]`，让 Markdown 打开时能直接显示。
7. 只做必要索引更新：更新所属目录 `_Index.md` 的文档路由表和本目录文档列表；不做大范围重构。
8. 原子卡片通过 `source_notes` 链接来源笔记；来源笔记的“已提炼知识”反向列出已创建卡片。
9. 高置信度卡片设置 `status: ready`、`route_to`、`route_reason`、`route_confidence`；置信度不足时设置 `status: needs-review` 并留在 Inbox。
10. 如果来源笔记已完成本轮精简提炼，将来源笔记设置为可归档路由，保留完整追溯链；不删除原文和附件。

## 知识理：保真模式

保真模式用于把来源笔记系统拆解成长期可复用知识，目标是“完整拆分、完整检索属性、完整追溯和路由”。

操作要求：

1. 排除文件名以 `_` 开头的说明文件。
2. 把来源笔记拆成 2–8 篇具有独立复用价值的原子卡片；没有足够价值时可以少于 2 篇，不为凑数量制造碎片。
3. 一张卡片应回答一个稳定问题，并包含独立结论、适用场景、方法或解释、示例以及限制；必须依赖上下文才能理解的内容继续合并保存。
4. 原子卡片使用 `05_Skills/0501_Knowledge Management/050101_Templates/知识卡片模板.md`，设置 `type: knowledge-skill`。
5. 每张卡片必须填写完整 Skill 式检索属性：`description`、`aliases`、`triggers`、`use_when`、`do_not_use_when`、`match_questions`、`parent_index`、`source_notes` 和 `related`。
6. `description` 使用“当用户需要……时使用。包含……；不包含……”格式，明确调用边界，不能只重复标题。
7. 原子卡片通过 `source_notes` 链接来源笔记；来源笔记的“已提炼知识”反向列出全部卡片。
8. 如果来源笔记或附件中有与原子卡片直接相关的图片、截图或图表，应尽量在对应文字说明之后引用图片，优先使用 Obsidian 可渲染的嵌入语法 `![[07_Attachments/...]]`，确保 Markdown 文档打开时能直接显示图片，保证图文并茂、便于用户理解；图片本体仍按附件规则保存在 `07_Attachments/`，原子卡片只嵌入或链接。
9. 为每张卡片选择 `route_to`，填写 `route_reason` 和 0–1 的 `route_confidence`。
10. 目标主题目录必须存在 `_Index.md`；新目录使用目录索引模板创建，已有目录则更新路由表。
11. 更新所属目录 `_Index.md` 的文档路由表、本目录文档列表和必要的相关知识包链接；必要时同步上级索引。
12. 置信度不低于 0.85 时设为 `status: ready`，运行路由脚本执行移动；低于 0.85 时设为 `status: needs-review`，继续留在 Inbox。
13. 原子卡片完成后，来源笔记路由到 `06_Archive` 的来源目录，保留完整追溯链，不删除原文。

## 知识理：共同安全底线

1. 无论精简还是保真，创建的 `knowledge-skill` 卡片都必须具备必要的 Skill 式检索属性。
2. 不编造来源、结论、链接或用户决策。
3. 图片、截图或图表本体仍保存在 `07_Attachments/`；卡片只嵌入或链接。
4. 低置信度内容宁可留在 Inbox，不强行路由。
5. 路由前应确认 `route_to`、`route_reason` 和 `route_confidence` 与卡片内容一致。

## 知识理：完成前自检清单

在报告 `知识理` 完成前，必须逐项自检：

1. 原子卡片是否回答一个稳定问题，且没有把多个无关主题硬塞进同一卡片。
2. 每张 `knowledge-skill` 是否具备必要 Skill 式检索属性：`description`、`aliases`、`triggers`、`use_when`、`do_not_use_when`、`match_questions`、`parent_index`、`source_notes`、`related`。
3. `description` 是否使用“当用户需要……时使用。包含……；不包含……”格式，并明确适用和排除边界。
4. `source_notes` 是否能回到来源笔记；来源笔记的“已提炼知识”是否反向列出本次创建的卡片。
5. 有关图片、截图、PDF 或图表的卡片，是否在对应文字说明后嵌入或链接附件，且附件路径存在。
6. 卡片中的关键结论、数字、代码、名称和示例是否能在来源笔记或附件中找到依据；不确定内容是否已标为限制、风险或待补充。
7. 所属目录 `_Index.md` 是否已更新文档路由表和本目录文档列表；必要时是否更新上级索引。
8. `route_to`、`route_reason`、`route_confidence` 是否与内容一致；低于 0.85 或边界不清的卡片是否留在 Inbox。
9. 执行路由前是否先预览；执行后是否确认 Inbox、目标文件、附件引用和路由脚本输出无异常。
10. 是否避免删除、覆盖、合并或移动用户未确认的来源资料和附件。

## Skill 式描述标准

正式知识卡片必须包含：

```yaml
type: knowledge-skill
description: >
  当用户需要……时使用。包含……；不包含……。
aliases: []
triggers: []
use_when: []
do_not_use_when: []
match_questions: []
parent_index:
source_notes: []
related: []
```

`description` 和 `use_when` 用于判断语义需求，`match_questions` 用于匹配真实提问，`triggers` 只辅助召回，`do_not_use_when` 用于排除相似但不适合的文档。

## 路由边界

| 目录 | 进入条件 | 不应进入的内容 |
|---|---|---|
| `01_Inbox` | 尚未提炼或需要人工确认 | 已完成处理的稳定笔记 |
| `02_Domains` | 可跨项目复用的专业或业务领域知识 | 单纯外部摘录 |
| `03_Areas` | 长期维护的领域知识 | 有明确结束时间的临时材料 |
| `04_Resources` | 外部参考与资料索引 | 已内化的方法或结论 |
| `05_Skills` | SOP、模板、清单、提示词 | 只说明“是什么”的概念笔记 |
| `06_Archive` | 已结束、过时或仅供追溯 | 仍需频繁使用的活跃知识 |
| `07_Attachments` | 非 Markdown 文件 | 知识正文 |

## 自动移动条件

自动移动必须同时满足：

```yaml
status: ready
route_to: 03_Areas/Research
route_confidence: 0.90
```

其中 `route_confidence` 必须不低于 `0.85`。脚本默认只预览，增加 `--apply` 后才执行移动。

## 文件夹编号

路由创建新文件夹时必须自动编号：

```text
05_Skills/0502_主题
05_Skills/0503_主题
06_Archive/0601_主题
05_Skills/0502_主题/050201_子主题
```

规则：

- 同级第一个新目录从 `01` 开始，之后取现有最大编号加一。
- 已存在的同名旧目录可以直接复用，不重复创建。
- 已存在但未编号的旧目录不会被脚本擅自重命名。
- 如果 `route_to` 使用无编号的新目录名称，脚本会生成编号并把最终路径回写到笔记属性。
- 手工创建目录或由 AI 直接创建目录时，也必须使用相同规则。

```powershell
# 预览
python ".agents/scripts/knowledge_router.py"

# 执行
python ".agents/scripts/knowledge_router.py" --apply

# 巡检
python ".agents/scripts/knowledge_router.py" --audit
```

## 巡检标准

执行 `知识巡` 时，先运行：

```powershell
python ".agents/scripts/knowledge_router.py" --audit
```

然后检查：

- Inbox 待处理笔记。
- 低置信度分类。
- 没有任何链接的候选孤立笔记。
- 已到 `review_after` 的笔记。
- 未完成任务。
- 重复、过时或可升级为 Evergreen 的内容。
- 缺少 `description` 或 Skill 式检索属性的知识卡片。
- 缺少 `_Index.md` 的知识主题目录。
- 根目录知识路由索引与实际目录不一致的条目。
- 知识收 / 知识理模式规则执行情况：
  - 来源笔记是否能看出本次按精简模式还是保真模式处理；未标明但内容明显依赖模式判断的，列为待改进。
  - 表格、CSV、TSV、Excel 等结构化资料是否默认按保真模式处理；若使用精简模式，是否明确说明 Markdown 不能替代原表。
  - 精简模式来源笔记是否因只提炼 1–2 张卡片而过早归档；若仍有重要未处理主题，应建议退回 Inbox 或标为 `needs-review`。
  - 图文资料提炼出的卡片是否在对应文字说明之后嵌入或链接相关图片、截图、PDF 或图表。
  - `07_Attachments/` 中最近新增附件是否至少被一篇 Markdown 来源笔记或知识卡片引用。

巡检只生成报告和建议；未经用户确认，不删除、合并或批量改写笔记。

## 关联标准

优先建立以下关系：

- 概念与应用
- 问题与解决方法
- 项目与所用技能
- 结论与来源
- 上位主题与下位知识卡片
- 新旧版本与替代关系

只有关键词相同而没有理解价值时，不建立链接。
